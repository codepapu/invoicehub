# InvoiceHub

One small invoicing app, built twice, so the two frameworks can be compared side by side.

| | [`openxava/`](openxava) | [`jmix/`](jmix) |
|---|---|---|
| Framework | OpenXava 8.0.1 (plain edition) | Jmix 3.1.1 |
| Stack | Spring Boot 4, Hibernate 7, generated UI | Spring Boot, Vaadin Flow, EclipseLink |
| Build | Maven | Gradle |
| Database | in-memory HSQLDB, reloaded from `import.sql` | HSQLDB file, Liquibase changelog |
| Run | `mvn spring-boot:run` | `./gradlew bootRun` |
| URL | http://localhost:8080/invoicehub | http://localhost:8080 |
| Login | `admin` / `admin` | `admin` / `admin` |

Both apps do the same things:

- Categories, products, customers and invoices with lines (CRUD, search, sort).
- Invoice number and date proposed automatically; unit price proposed from the product.
- Live amounts sum, VAT and total on the invoice form.
- Customer form with the list of that customer's invoices.
- **Print invoice (PDF)** button on the invoice form.
- The same seed data (2 invoices: totals 3,960.00 and 3,511.80).

Both editions validate the same rules (unique invoice number, VAT 0-100, quantity >= 1,
unit price >= 0, at least one line) and ship with unit tests (`mvn test` / `./gradlew test`).

## How they compare

| | OpenXava | Jmix |
|---|---|---|
| Hand-written lines (Java + XML + properties, rough) | ~780 | ~2,900 |
| Screens | Generated from entity annotations (`@View`, `@Tab`, `@DescriptionsList`) | One XML descriptor + Java controller per view |
| Customer-to-invoices | One `@OneToMany @ReadOnly` field | Property container, grid and fetch plan in XML |
| Calculated totals | `@Depends` getters, UI refreshes itself | `@JmixProperty @DependsOnProperties` plus code in the view to refresh the unbound fields |
| PDF | JasperReports (`JasperReportBaseAction` + `Invoice.jrxml`), free | OpenPDF in a service class; the Reports add-on is commercial |
| Schema | Generated by Hibernate | Written in Liquibase |
| UI control | Limited, consistent look | Full Vaadin components, fully customisable |
| First start | Seconds | Minutes (frontend bundle build) |
| Security | Simple user file | Role-based access with row/attribute policies |

Rule of thumb: OpenXava gets a back-office CRUD app running with very little code. Jmix costs more
code up front but gives finer control over screens, security and layout.

## Gotcha worth knowing

Jmix only loads the attributes in a view's fetch plan. The PDF button first failed with
`Cannot get unfetched attribute [city] from detached object Customer` until the invoice view's
customer fetch plan was changed from `_instance_name` to `_base`.
